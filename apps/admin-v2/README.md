# @scalius/admin-v2 - Merchant dashboard

A static single-page app for contributors: Vite, TanStack Router, TanStack Query, React 19, shadcn/ui on Radix and Tailwind CSS v4. It has no Worker, Wrangler config, secrets or bindings. `vite build` writes `dist/`. The API Worker (`scalius-api`) serves that folder from its `ASSETS` binding on the dashboard hostname, together with Better Auth (`/api/auth/*`), the scanner cookie exchange (`/api/scanner-token`) and the API (`/api/v1/*`). That code is in `apps/api/src/dashboard/`. UI rules are in [DESIGN.md](./DESIGN.md).

## Run locally

1. Run `pnpm dev:setup` once from the repository root. It creates the local secrets, applies local D1 migrations and creates a default local admin.
2. Run `pnpm dev:admin` from the root. It starts the API Worker on `:8787` and the dashboard on `:4323`.

Vite proxies `/api/v1`, `/api/auth` and `/api/scanner-token` to the API Worker, so development and production use the same same-origin paths. `scripts/dev-ports.mjs` owns the ports (`SCALIUS_DEV_ADMIN_PORT`, `SCALIUS_DEV_API_PORT`). See "Parallel local stacks" in the [root README](../../README.md).

## Build rules

- `index.html` is a blank shell. The API Worker writes the runtime base path into a `<meta>` tag and into every root-relative asset URL, so one build serves any path prefix (`src/lib/dashboard-base-path.ts`).
- The dashboard reads no env. `vite.config.ts` sets `envDir: false`. Never write a bare `import.meta.env` or `process.env`. `pnpm check:dist-secrets` and `pnpm check:build-canaries` check the output.
- Import `@scalius/core` only as `@scalius/core/modules/<domain>/browser` or `@scalius/core/auth/rbac/*`. `src/lib/browser-core-boundaries.test.ts` enforces the domain rule.
- The build fails when `dist/` JavaScript contains a relational provider marker (D1, Turso or database client strings), on a reciprocal static chunk import, and on a broken immutable-asset header rule in `public/_headers`. Hashed JS, CSS and fonts live under `/assets/immutable/` with one-year immutable headers.
- Keep the `$initial` Rolldown group in `vite.config.ts` unsplit. A size cap can split the router's strongly connected ESM graph and crash the app before sign-in.
- `admin-perf-check.mjs` keeps heavy libraries (Tiptap, QR scanner, PDF) out of a route's first download. Raise a budget only with a reason in the commit.

## Data flow

```
SDK call (@scalius/api-client/sdk) unwrapped once by apiData() in src/lib/api.ts
  -> queryOptions wrappers (src/lib/api-query-options/)
    -> warmRouteQuery() or ensureQueryData() in the route loader
      -> useQuery or useSuspenseQuery in the component
        -> mutation hooks (src/lib/api-mutations/) that invalidate queries and toast
```

- **Transport.** `src/lib/api.ts` points the SDK client at one `fetch`: same-origin `<base>/api/v1/*` with `credentials: "same-origin"` and `cache: "no-store"`. The API answers `{ success, data }`. `apiData()` unwraps it and throws `AdminApiResponseError` on failure.
- **Timeouts.** `GET` and `HEAD` stop after `ADMIN_API_READ_TIMEOUT_MS` (15 s). Writes never time out, so a committed write is not reported as failed.
- **Freshness.** Each query-options module sets its own `staleTime` (30 s for order and inventory lists up to 30 min for settings). The client default is `ADMIN_QUERY_STALE_TIME_MS` (10 s). Detail queries use `staleTime: 0`. Most edit routes prefetch with `Infinity`, so a visit shows cached data and refetches in the background. The product editor fetches fresh data unless a hover started the read in the last 5 s.
- **Lists.** Page state lives in URL search params. The route declares `loaderDeps` and prefetches the query key the component renders. `useServerTable()` handles page-number lists and cursor lists (`pageInfo`).
- **Idle tabs.** The client keeps data for 30 min and does not refetch on focus or reconnect. It uses `networkMode: "always"` and `retry: false`, so an offline save fails at once and never replays later. Only live screens poll: order detail (30 s), the inbox, and the order-list auto-refresh (off by default, visible tab only).
- **Scroll.** The router restores scroll on the `#admin-main-scroll` container: Back and Forward restore it, a new visit starts at the top. Do not add `scrollTo()` calls on route change.

## Session and routing

- Every guard decision comes from one read of `GET <base>/api/auth/dashboard-session`. `index.html` starts that read before the app downloads, and `src/main.tsx` resolves the first route before it renders. Protected content never flashes for a signed-out visitor.
- `adminRouteGuard()` redirects a missing session, a forced password change, a missing 2FA enrollment and an unverified 2FA to the matching `/auth/*` page. `/admin` then checks RBAC with `shouldAllowAdminPath()` (`src/lib/admin-access.ts`). The guards only redirect. The admin API enforces the same gates on every call.
- `admin-route-context.ts` caches the verified context for 60 s and serves it stale for up to 4 hours while it refreshes in the background. Code that changes the user's profile, 2FA state, session or permissions must call `refreshAdminRouteContext(router)`.
- Auth, setup and 2FA success paths navigate with the router, never with a full reload. A form that navigates passes no Better Auth `callbackURL`.
- `/connect` (CLI pairing) needs a super admin and re-reads the session with `getFreshAdminRouteContext()`.

## Navigation performance

- Links use `preload="intent"`. The router runs loaders on every preload (`defaultPreloadStaleTime: 0`) and React Query decides freshness. The router keeps the current page mounted while it navigates, and `AdminNavigationProgress` shows a progress bar only after 180 ms.
- After the first page settles, `useWarmEverydayRouteCode()` downloads only the route code of orders, products, customers and inventory. It runs no loaders and skips Save Data and 2G connections. `useServerTable()` skips only the duplicate fetch within 5 s of an intent preload (`INTENT_PREFETCH_MOUNT_GRACE_MS`).
- Do not warm adjacent Orders or Customers pages. Do not bulk-sync protected data. Read [docs/PERFORMANCE-RELEASE.md](../../docs/PERFORMANCE-RELEASE.md) before you change pending behavior, add virtualization or widen preloading.

## Forms and settings

- `useSettingsForm()` keeps the draft and the last saved copy. A refresh keeps the fields the merchant edited and adopts the rest, comparing each top-level field as one value. A settings save sends `expectedRevision`. On a revision conflict the merchant can choose "Reload and keep my edits". The save never overwrites silently.
- Forms register with `SaveBar`, which owns Save, Discard and the error banner. `UnsavedChangesGuard` blocks navigation and the browser `beforeunload` while a form is dirty.
- `useEntityFormSubmit()` creates or updates a record, invalidates the listed query keys and rejects with `SaveNotCompleted` on failure.
- Checkout settings read `/api/v1/admin/settings/checkout-readiness`. Requiring customer accounts stays blocked until customer sign-in is usable.
- Platform settings: Settings > Store details > Web addresses sets the public origins (`StoreSettings.tsx`). Settings > Advanced > Sign-in and access sets single sign-on, the customer cookie domain, extra CORS origins and the setup token (`AdvancedSettings.tsx`). Both use `GET` and `PUT /api/v1/admin/settings/platform`. The Workers read the public part at `GET /api/v1/platform`.

## Copy and language

Copy lives in `src/i18n/<feature>.ts`. Each file calls `defineMessages({ en, bn })`, and the type requires every `en` key in `bn`. Components call `useMessages(catalog)`. `i18n/index.ts` formats numbers (lakh grouping) and dates (Asia/Dhaka) for the active locale and saves the choice in `localStorage` (`scalius.dashboard.locale`). `vocabulary.test.ts` keeps one Bangla word per idea.

## Notes on screens

- **Scanner pairing.** `POST /api/v1/admin/auth/scanner-link` needs `products.view` and `products.edit` (super admins pass). It stores a one-time token claim. `/api/scanner-token` exchanges the token for a scanner cookie. Tokens never appear in URLs.
- **Order detail** (`components/admin/orderview/`). `ManualFulfillmentDialog` records hand-over by line quantity for three kinds: ship, pickup and service. `ShipmentCard` shows a recovery notice. Its repair and courier-check actions appear only to users who can manage shipments.
- **Status badges.** `orderview/status-badges.ts` and `resource/StatusBadge.tsx` map statuses to badge variants. DESIGN.md has the table.
